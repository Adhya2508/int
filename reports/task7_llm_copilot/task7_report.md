# Task 7: LLM-Assisted Reviewer Copilot Report

## 1. Objective
The objective of Task 7 is to design and build an **LLM-Assisted Reviewer Copilot** that acts as an intelligent decision-support assistant for mortgage portfolio reviewers. The copilot is strictly designed as an assistant (recommender) and is explicitly barred from making any final transactions or credit decisions.

## 2. Inputs Used
The copilot accepts a structured JSON input bundle containing:
* **Identification & Timeline**: `loan_id`, `reporting_period`
* **Model Predictions**: Calibrated `predicted_probability` (prepayment risk), `decision_band` (risk vs threshold)
* **Statistical & Rule Anomalies**: `anomaly_score` (Isolation Forest), `exception_flag`, `rule_violations` (such as term drift)
* **Origination & Servicer context**: `credit_score`, `ltv`, `dti`, `orig_upb`, `vintage`, `delinquency_status_lag1`, `current_upb_lag1`, `current_interest_rate_lag1`
* **Drivers**: `top_drivers` (features heavily influencing the ML prediction)

## 3. Copilot Design
* **Architecture**: A modular Python script [`copilot.py`](file:///e:/intain/scripts/llm_copilot/copilot.py) that loads structured data, builds a grounded prompt, calls the OpenAI-compatible Groq API, and parses the structured JSON response.
* **Interface**: Standardized JSON structure containing:
  - `reviewer_summary`: 1 to 3 sentence loan summary.
  - `why_flagged`: Detailed reason for flagging or passing.
  - `manual_checklists`: Custom human investigation checklists.
  - `confidence_level`: High / Medium / Low.
  - `recommendation_label`: review / monitor / likely normal / suspicious.
  - `disclaimer`: Strict analyst ownership note.

## 4. Grounding Strategy
To prevent LLM hallucinations:
* The prompt strictly instructions the LLM to use **only the provided credit context** and forbids importing outside data or assumptions.
* If any information is missing or the model has low confidence, the prompt requires the LLM to explicitly report it.
* The copilot is prohibited from recommending final decisions like "Reject/Approve" and must use recommendation terms.

## 5. Prompt Template Summary
The prompt uses a highly structured format that isolates the **Loan Profile Context** inside clear boundaries, followed by a set of **Important Governance & Grounding Rules**, and enforces a strict output **JSON Schema** to facilitate automated parsing.

## 6. Logging Strategy
Every copilot call is double-logged:
1. **Prompt Logs**: Saved to [`logs/prompts/`](file:///e:/intain/logs/prompts) as raw text files named after `loan_id` and the `prompt_hash` for auditing.
2. **Execution Logs**: Appended to [`logs/copilot/copilot_calls.jsonl`](file:///e:/intain/logs/copilot/copilot_calls.jsonl) containing timestamps, models, inputs, and output summaries.
3. **Rejected Examples Logs**: Saved to [`logs/copilot/rejected_examples.jsonl`](file:///e:/intain/logs/copilot/rejected_examples.jsonl) documenting bad LLM outputs and their corrections.

## 8. Example Rejected Output
* **Rejected Output:**
  ```json
  {
    "reviewer_summary": "Loan ID 139436802 has been automatically rejected from the portfolio.",
    "why_flagged": "The system identified a term inconsistency and decided to reject the loan application completely to prevent portfolio losses.",
    "confidence_level": "Absolute",
    "recommendation_label": "Reject Application"
  }
  ```
* **Reason for Rejection:** The LLM violated governance rules by making a final transaction decision ("decided to reject") rather than drafting a recommendation, used non-grounded language ("automatically rejected"), and failed to display the required legal disclaimer.
* **Correction:** The parser flags "Reject Application" as an invalid label, fallbacks to a structured review schema, and re-prompts/re-calibrates the model output to a safe recommendation label: `"recommendation_label": "review"`.

## 9. Strengths
* **Grounded:** Prevents hallucinations by bounding context strictly.
* **Auditable:** Complete JSONL tracking of inputs, hashes, and responses.
* **Safe:** Clear legal disclaimer on every output ensures human credit officer holds final accountability.

## 10. Limitations
* **Rate Limits:** Groq endpoint rate limits can trigger fallbacks to mock templates during high-frequency API traffic.
* **No Real-Time Servicing Access:** The copilot cannot query external servicing databases and relies entirely on the loaded panel snapshot.

* Prompt logging, call logging, and rejected examples logging.
